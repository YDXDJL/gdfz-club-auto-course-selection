课程请求工具 · 多账号与定时发送

启动
关闭旧窗口，双击桌面的“报名请求测试”快捷方式。
请保持同目录下的 course_app.py、request_engine.py、courses.json 与启动脚本在一起。

1. 选择课程
选择报名或收藏，然后选择“全部 / 选修课 / 社团课”分类。
支持按课程名称、课程 ID 搜索，也可直接填写课程 ID。
默认活动 3389，默认课程“阳光心理社”（265899429）。
截至 2026-09-12，网页标称 86 门，但当前账号目录实际返回 56 门：选修课 35 门、社团课 21 门，均已内置。
“刷新全部账号可见课程”读取各已添加账号正常可见的目录并合并；只能收录接口实际返回的课程。
刷新结果只保存课程资料，不保存账号 Cookie。任一账号刷新失败时保留原目录。

2. 添加账号 Cookie
在已登录网页按 F12 → Network，刷新后选择该站点请求。
从 Headers → Request Headers 复制 Cookie 的完整值。
在程序里填写备注与 Cookie，再点击“添加”。每个账号重复一次。
也可点击“批量添加”，每行粘贴一个账号完整 Cookie；完全重复的 Cookie 自动去重。
Cookie: 前缀和 Markdown 的下划线转义会自动清理。
已添加账号全部参与发送，选中账号行仅用于“移除选中”，不影响参与范围。
所有账号使用当前所选的同一门课程和同一种操作。
Cookie 仅保存在进程内存中，不写入文件；重启后需重新添加。

3. 定时与轮次
北京时间格式：YYYY-MM-DD HH:MM:SS.fff
示例：2026-09-13 10:00:00.123，最后三位是毫秒。
轮数：1–10000。轮间等待：0–86400000 毫秒。
“轮间等待”从上一轮所有账号请求结束后开始计时，再执行下一轮。
例如 3 个账号、4 轮：未取消且无任务级异常时，共发出 12 次请求。
每轮每个账号各发送一次，最多 8 个账号并行；更多账号会在本轮排队。
即使某账号之前返回成功，后续轮次仍会按你的设定继续发送。
“立即开始”立刻执行设定轮数；“启动定时”等待指定时间后执行相同轮数。
点击“预览任务”仅显示参数和总次数，不发送请求。
启动后参数锁定，可点击“停止 / 取消定时”终止后续发送；已经发出的请求无法撤回。

时间精度
时间输入与日志精确到毫秒。Windows 运行任务时临时请求 1ms 定时器分辨率，结束后恢复；线程在定时时刻前预热。
操作系统调度、请求准备、网络延迟及服务器排队仍会影响实际时间，不能保证服务器精确在指定毫秒收到请求。
定时期间须保持程序运行、电脑唤醒且网络连通；关闭程序不会在后台继续定时。
请求超时为 20 秒；日志中的时间是客户端请求开始时间，耗时包含网络和响应处理。

4. 查看结果
绿色“成功”：HTTP 为 2xx 且 JSON 中 status 是布尔值 true。
红色“失败”：HTTP 非 2xx 或 status 是布尔值 false，并显示 msg 提示。
黄色“待核对”：缺少布尔值 status、返回非 JSON、网络异常或超时。
不会把 HTTP 200、字符串“false”或其他非布尔值当作成功。
账号表显示最近结果，日志列出轮次、账号、时间、耗时与提示；点击日志查看响应正文。
界面保留最近 2000 条明细，当前任务的总计不受此限制。
超时可能意味着请求已到服务器；最终状态请在网站的收藏列表或已选课程中核对。
